## 1. 새로운 통합 요구사항 분석

### 1.1 일레븐랩스(ElevenLabs) 음성 AI 상담

#### 현재 상황
- 메신저/카톡만으로 상담
- 전화 상담은 여전히 수동

#### 일레븐랩스 도입 효과

```
기존:
고객이 전화 → 직원이 받음 → 수동으로 기록 → 실수 및 대기시간

고도화:
고객이 전화 → IVR (AI 음성) → 자동 응답 + 텍스트 변환 
            → 예약 자동생성 
            → 직원에게 알림 (필요시만)
```

**일레븐랩스 기술 특징:**
- **음성→텍스트**: 실시간 STT (Speech-to-Text)
- **음성 합성**: TTS (Text-to-Speech) - 자연스러운 한국어
- **다중 언어**: 영어, 중국어 등 (v2.0+)
- **감정 분석**: 고객 감정 상태 파악 (VIP 고객 감지)
- **통화 녹음 & 저장**: 감시/학습용

**기술 통합 포인트:**
```
전화 입력 (Twilio 또는 SKT/KT PBX)
    ↓
IVR 시스템 (일레븐랩스 음성 AI)
    ├─ "안녕하세요 ElSpa입니다!"
    ├─ "1. 예약, 2. 스케줄 확인, 3. 상담원 연결?"
    └─ 고객 음성 입력
    ↓
음성 인식 (STT) + 의도 파악
    ├─ "내일 스웨디시 60분"
    └─ → 자동상담 에이전트로 라우팅
    ↓
예약 생성 또는 상담원 전달
```

**새로운 요구사항:**
- [ ] 전화 번호 → 고객 정보 자동 매칭 (CRM)
- [ ] 전화 통화 중 실시간 예약 생성 (고객: "예약됐나요?" → AI: "네, 확정되었습니다")
- [ ] 음성 통화 기록 저장 (학습용)
- [ ] VIP 고객 자동 감지 → 상담원 우선 연결
- [ ] 야간/휴무일 자동응답 ("내일 09:00에 전화드리겠습니다")

**기대 효과:**
- 24/7 전화 상담 가능 (음성 AI)
- 상담 누락 0% (텍스트로 모두 기록)
- 직원 콜센터 비용 30~50% 감축

### 1.2 칼닷컴(Cald.com) 스케줄 플랫폼 연동

#### 현재 상황
- 구글시트로 수동 예약 관리
- 칼닷컴(외부 예약 플랫폼)이 이미 사용 중일 수 있음
- 양쪽 시스템 간 동기화 문제

#### 칼닷컴 분석

**칼닷컴이란:**
- 미용/마사지/스파 전문 예약 관리 SaaS
- 매장 고객이 온라인으로 예약하는 플랫폼
- 이미 고객들이 사용 중일 가능성

**통합 필요성:**
```
문제: 중복 예약 가능성
┌──────────────┐         ┌──────────────┐
│ 칼닷컴       │ 예약1   │ ElSpa        │
│ (고객 예약)  │────────→ (DB)          │
├──────────────┤         │ 스케줄 뷰    │
│ 시간: 14:00  │  동기화 │ 충돌 감지    │
│ 테라피스트: 김│  문제   │ 누락됨!!!    │
└──────────────┘         └──────────────┘
```

**칼닷컴 API 통합 방식:**

```
Option A: Webhook (실시간)
칼닷컴 예약 생성 → Webhook → ElSpa DB 업데이트
↓ (5초 이내)
ElSpa 스케줄 뷰에 반영

Option B: API Polling (정기적)
매 1분마다: 칼닷컴 API 호출 
→ 새 예약 확인 
→ ElSpa DB 동기화

Option C: Bidirectional Sync
ElSpa 예약 생성 → 칼닷컴에도 동시 생성
```

**새로운 요구사항:**
- [ ] 칼닷컴 Webhook 수신 및 검증
- [ ] 실시간 양방향 동기화 (ElSpa ↔ 칼닷컴)
- [ ] 중복 예약 감지 & 자동 취소 규칙 (어느 쪽을 우선?)
- [ ] 고객 정보 동기화 (전화, 이름)
- [ ] 취소/수정도 동기화
- [ ] 시간대 공유 (칼닷컴에서 "13:00-14:00" 예약 불가 표시)

**기대 효과:**
- 기존 칼닷컴 고객들도 ElSpa 시스템 활용 가능
- 중복 예약 0%
- 예약 채널 통합 (칼닷컴 + 메신저/카톡 + 전화 = 하나의 스케줄)

**기술 위험:**
- 칼닷컴 API 문서 품질 (지원 부족 가능)
- 칼닷컴 API Rate Limit (초과 시 처리)
- 데이터 불일치 시 복구 프로토콜 필요

### 1.3 구글캘린더 연동

#### 현재 상황
- 테라피스트가 개인 구글캘린더 사용 (가능)
- 직원 스케줄과 일정이 동기화되지 않음

#### 구글캘린더 통합 필요성

```
테라피스트 일정 관리:
┌─ 업무 일정 (예약된 고객들)
├─ 개인 일정 (휴식, 병원, 회의)
└─ 구글캘린더와 동기화 필요

이유:
- 테라피스트가 개인 캘린더를 주로 사용함
- "어, 나 13:00에 의사 가기로 했는데?"
- ElSpa 시스템이 자동으로 OFF 처리해달라고 요청
```

**통합 방식:**

```
Option A: ElSpa → Google Calendar (일방향)
ElSpa 스케줄: 13:00 김철수 예약
    ↓
구글캘린더 API로 자동 추가:
"ElSpa: 고객 김××님 스웨디시 (13:00-14:00)"
    ↓
테라피스트는 이미 구글캘린더에서 일정 확인 가능

Option B: Google Calendar ↔ ElSpa (양방향)
테라피스트가 구글캘린더에 개인 일정 추가:
"의사 진료 (14:00-15:00)"
    ↓
Webhook으로 ElSpa에 알림
    ↓
ElSpa가 자동으로 해당 시간 OFF 처리
    ↓
해당 시간 예약 불가 표시
```

**새로운 요구사항:**
- [ ] 구글 OAuth 2.0 인증 (사용자별)
- [ ] 테라피스트 구글계정 연동 옵션
- [ ] ElSpa 예약 → 구글캘린더 자동 추가
- [ ] 구글캘린더 "Busy" 감지 → ElSpa OFF 처리
- [ ] 동기화 충돌 시 알림 (사용자 승인 요청)
- [ ] 구글캘린더 접근권한 관리 (ElSpa만 보기 가능)

**기대 효과:**
- 테라피스트의 이중 관리 필요 없음
- 개인 일정과 업무 일정 자동 조율
- "일정 충돌" 실수 감소

## 4. 기술 통합 포인트 상세

### 4.1 음성(ElevenLabs) 통합 흐름

```
[고객이 전화]
(SKT 또는 기존 회선)
    ↓
[PBX IVR - Twilio 또는 자체]
"안녕하세요 ElSpa입니다"
    ↓
[ElevenLabs STT 엔진]
음성 → 텍스트: "스웨디시 60분 해주세요"
    ↓
[AI 상담 에이전트 (LangGraph)]
텍스트 처리 → 의도 파악 → 예약 검색
    ↓
[ElevenLabs TTS]
"네, 내일 14:00 스웨디시 60분 확정하시겠어요?"
    ↓
[STT 대기]
고객: "네"
    ↓
[예약 생성]
DB에 저장 + 직원에게 알림
```

**필요한 API:**
- Twilio Voice API (전화 수신)
- ElevenLabs Conversational AI API
- Custom IVR 로직

**기술 도전:**
- 실시간 음성 처리 (100ms 이내 응답)
- 한국어 음성 인식 정확도 (방언, 배경 소음)
- 통화 끊김 시 처리

### 4.3 구글캘린더 통합 흐름

```
[테라피스트 권한 부여]
"이 앱이 내 구글캘린더에 접근해도 되나?"
    ↓
[OAuth 2.0 흐름]
- 권한 부여 화면
- Refresh token 저장 (DB)
    ↓
[자동 동기화 1: ElSpa → Google]
ElSpa 예약 생성:
"내일 14:00, 김철수 - 스웨디시"
    ↓
Batch Job (매시간)
Google Calendar API:
```
events.insert()
title: "ElSpa: 고객 김××님 스웨디시"
time: 2026-05-06 14:00-15:00
description: "예약 ID: #RES-00234"
```
    ↓
[자동 동기화 2: Google ← ElSpa]
테라피스트가 구글캘린더에 추가:
"병원 진료 (14:00-15:00)"
    ↓
Webhook으로 감지 (또는 매 30분 폴링)
    ↓
ElSpa 스태프 가용성 업데이트:
staff_unavailable: ["2026-05-06 14:00:00"]
    ↓
스케줄 뷰: 해당 시간 OFF 표시
```

**필요한 API:**
- Google Calendar API v3
- Google OAuth 2.0
- Calendar Events CRUD

**기술 도전:**
- Timezone 처리 (UTC vs KST)
- 권한 갱신 실패 처리
- 병렬 업데이트 충돌

## 9. 핵심 통찰 & 제언

### 통찰 1: 데이터 동기화 복잡도
```
복잡도 증가:
기존 (단일 앱) → 새로운 (3가지 앱 + 외부 플랫폼)

동기화 포인트 증가:
3개 → 5개 (칼닷컴, 구글캘린더 추가)

위험: 데이터 불일치 가능성 높아짐
해결: Event Sourcing, 감시/알림 시스템 강화
```

### 통찰 2: 음성 상담의 높은 기술 난이도
```
ElevenLabs는 매력적이지만:
- 실시간 처리 복잡
- PBX 통합 필요
- 한국어 정확도 검증 필요

제안: MVP(텍스트)로 검증 후 Phase C에서 추가
```

### 통찰 3: 사이트 분리의 이점
```
보안:   권한 분리 명확 (레이어 분리)
성능:   필요한 데이터만 로드
UX:     각 사용자에 최적화
운영:   버그 격리 (Admin 버그가 User에 영향 없음)
```
