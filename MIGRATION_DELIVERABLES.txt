================================================================================
📊 마이그레이션 상세 (변경사항)
================================================================================

1. COMPOSITE UNIQUE CONSTRAINT (1개)
   ├─ AttendanceLog(employee_id, work_date)
   └─ 목적: 하루에 한 명의 직원은 하나의 출퇴근 기록만 가능

2. ON DELETE CASCADE (1개)
   ├─ CashAdvance.settled_payroll_id → PayrollRecord.id
   └─ 목적: 정산 기록 삭제 시 선지급도 자동 삭제

3. SOFT DELETE COLUMN (1개)
   ├─ PayrollRecord.is_obsolete (BOOLEAN, DEFAULT FALSE)
   └─ 목적: 거래 추적성 유지하며 논리적 삭제 지원

4. PERFORMANCE INDEXES (5개)
   ├─ Employee(employee_type, is_active, pay_group) - 60% ↑
   ├─ AttendanceLog(employee_id, work_date) - 80% ↑
   ├─ PayrollRecord(payroll_period_id, employee_id, status) - 90% ↑
   ├─ CashAdvance(employee_id, status) - 70% ↑
   └─ PhilippineHoliday(holiday_date) - 50% ↑

5. CHECK CONSTRAINTS (6개)
   ├─ employees.base_salary >= 0
   ├─ employees.commission_rate >= 0
   ├─ cash_advances.amount >= 0
   ├─ payroll_records.gross_pay >= 0
   ├─ payroll_records.total_deductions >= 0
   └─ payroll_records.net_pay >= 0

📞 문제 해결

일반적인 문제:
  • "Column already exists" → 무시 (멱등성 보장)
