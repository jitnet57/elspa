================================================================================
ELSPA Massage Booking System - Entity Relationship Diagram (Text-based ER)
================================================================================

Overview:
- Customers → Bookings → Therapists (many-to-many relationship)
- Bookings → Services, Beds (one-to-many)
- Therapists → Attendance, Settlement, Reviews (one-to-many)
- Daily & Therapist Settlements for financial tracking
- Matching Logs for algorithm transparency

================================================================================
DATA FLOW DIAGRAM
================================================================================

1. BOOKING LIFECYCLE
═════════════════════════════════════════════════════════════════════════════

   고객 예약 요청
   ├─ status = 'requested'
   │
   ▼
   매칭 알고리즘 실행
   ├─ MATCHING_LOGS 기록
   ├─ therapist_id 결정
   └─ status = 'matched'
   │
   ▼
   고객 확정
   ├─ beds.id 할당
   └─ status = 'confirmed'
   │
   ▼
   시술 시작 (scheduled_at 시간에)
   ├─ started_at 기록
   ├─ beds.status = 'in_service'
   └─ status = 'in_progress'
   │
   ▼
   시술 완료
   ├─ ended_at 기록
   ├─ therapist_commission 계산
   │  = paid_amount * commission_rate
   ├─ beds.status = 'available'
   ├─ customers.total_visits += 1
   ├─ customers.total_spent += paid_amount
   ├─ customers.points += (paid_amount * 0.05)
   └─ status = 'completed'
   │
   ▼
   정산 처리 (매일 자정 JOB)
   ├─ therapist_attendance 자동 갱신
   ├─ therapist_settlements 생성
   └─ daily_settlements 생성


2. DAILY SETTLEMENT WORKFLOW
═════════════════════════════════════════════════════════════════════════════

   매일 00:00 (자정) 정산 JOB 실행:

   FOR EACH therapist:
      ├─ 전일 완료 bookings 조회
      │  WHERE therapist_id = ? AND DATE(ended_at) = ?
      │
      ├─ therapist_attendance 업데이트
      │  ├─ total_sessions = COUNT(completed bookings)
      │  ├─ total_revenue = SUM(paid_amount)
      │  ├─ total_commission = total_revenue * commission_rate
      │  └─ status = 'settled'
      │
      └─ therapist_settlements 생성
         ├─ session_count, total_revenue 복사
         ├─ commission_earned = total_revenue * commission_rate
         └─ status = 'settled'

   AGGREGATE daily_settlements:
      ├─ total_revenue = SUM(therapist_settlements.total_revenue)
      ├─ total_commission = SUM(therapist_settlements.commission_earned)
      ├─ net_profit = total_revenue - total_commission
      └─ 기타 통계 계산


3. COMMISSION CALCULATION
═════════════════════════════════════════════════════════════════════════════

   신인 (novice): commission_rate = 50%
      ├─ 80,000원 → 40,000원 커미션
      └─ 플랫폼 순이익 = 40,000원 (50%)

   중급 (intermediate): commission_rate = 45%
      ├─ 80,000원 → 36,000원 커미션
      └─ 플랫폼 순이익 = 44,000원 (55%)

   경력 (experienced): commission_rate = 40%
      ├─ 80,000원 → 32,000원 커미션
      └─ 플랫폼 순이익 = 48,000원 (60%)

EXAMPLE QUERIES
================================================================================

-- 실시간 예약 매칭: 현재 이용 가능한 테라피스트
SELECT id, name, rating, commission_rate
FROM therapists
WHERE status IN ('idle', 'resting')
  AND specialty LIKE '%스웨디시%'
ORDER BY rating DESC, total_sessions ASC
LIMIT 5;


-- 특정 테라피스트의 하루 매출
SELECT
  t.name,
  COUNT(b.id) as sessions,
  SUM(b.paid_amount) as total_revenue,
  SUM(b.therapist_commission) as commission
FROM therapists t
LEFT JOIN bookings b ON t.id = b.therapist_id
  AND b.status = 'completed'
  AND DATE(b.ended_at) = CURRENT_DATE
WHERE t.id = 1
GROUP BY t.id, t.name;


-- 플랫폼 전체 일일 정산 (INSERT로 daily_settlements 생성)
INSERT INTO daily_settlements (settlement_date, total_revenue, total_commission, net_profit)
SELECT
  CURRENT_DATE - INTERVAL '1 day',
  SUM(b.paid_amount),
  SUM(b.therapist_commission),
  SUM(b.paid_amount) - SUM(b.therapist_commission)
FROM bookings b
WHERE DATE(b.ended_at) = CURRENT_DATE - INTERVAL '1 day'
  AND b.status = 'completed';


-- 현재 마사지룸1의 가용 침대
SELECT bed_number, capacity, features
FROM beds
WHERE room_zone = '마사지룸1' AND status = 'available'
ORDER BY bed_number;


-- VIP 고객 (총 방문 10회 이상, 내림차순)
SELECT id, name, total_visits, total_spent, points
FROM customers
WHERE total_visits >= 10
ORDER BY total_spent DESC;


================================================================================
DESIGN NOTES
================================================================================

1. TEMPORAL CONSISTENCY
   - created_at, updated_at 모든 테이블에 자동 추가
   - `updated_at` = NOW() 트리거로 자동 갱신
   - 시간대: TIMESTAMPTZ (시간대 독립적)

2. SOFT DELETES (논리적 삭제)
   - 데이터 무결성 유지
   - 감시 기록 보존
   - status='deleted' 또는 deleted_at 추가 권장

3. AUDIT LOGGING
   - 정산 관련 변경 사항은 별도 로그 테이블
   - commission 변경, status 변경 등 추적

4. SCALABILITY
   - 파티셔닝: bookings, daily_settlements를 날짜로 파티셔닝 가능
   - 읽기 복제본: SELECT 쿼리 성능 개선
   - 캐싱: Redis로 실시간 상태 캐싱

5. DATA INTEGRITY
   - NOT NULL 제약으로 필수값 보장
   - CHECK 제약으로 값의 범위 확인 (rating 1~5 등)
   - UNIQUE 제약으로 중복 방지
