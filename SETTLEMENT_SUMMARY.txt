🎯 핵심 규칙 (3가지)
================================================================================

정산 유형별 처리 방식:

┌─────────────────┬──────────────┬──────────────┬──────────┐
│ 고객 유형       │ 정산 상태    │ 설명         │ 회수율   │
├─────────────────┼──────────────┼──────────────┼──────────┤
│ Guest (비회원)  │ SETTLED      │ 즉시 정산    │ 100%     │
│ Credit (외상)   │ PENDING      │ 대기 정산    │ 0~100%*  │
│ Waived (제외)   │ WAIVED       │ 정산 제외    │ 0%       │
└─────────────────┴──────────────┴──────────────┴──────────┘

* 회수율은 관리자가 월별로 수기 갱신

================================================================================
📊 계산 공식 (5가지)
================================================================================

1. 매출 분류
   total_revenue = guest_revenue + credit_revenue + waived_revenue

2. 외상 회수액
   recovered_amount = credit_revenue × (recovery_rate / 100)
   예) 100,000 × 80% = 80,000

3. 플랫폼 수수료
   base_amount = total_revenue - waived_revenue
   platform_fee = base_amount × (platform_fee_rate / 100)
   예) 250,000 × 25% = 62,500

4. 차감액 합계
   total_deductions = refund + dispute + other
   예) 5,000 + 2,000 + 1,000 = 8,000

5. 최종 정산액 (핵심)
   net_settlement = (guest_revenue + recovered_amount)
                  - platform_fee
                  - total_deductions

   예) (150,000 + 80,000) - 62,500 - 8,000 = 149,500 PHP

================================================================================
🔄 정산 워크플로우 (5단계)
================================================================================

[월초]
   ↓
   Step 1: 데이터 수집 (지난달 예약)
   → booking + customer + transaction 통합
   → settlement_type별 분류 (guest/credit/waived)

   ↓
   Step 2: 자동 계산 (상태: DRAFT)
   → SettlementCalculator 실행
   → 매출, 회수, 수수료, 차감 계산

   ↓
   Step 3: 관리자 검증 및 승인 (상태: APPROVED)
   → 외상 회수율 수기 갱신
   → 분쟁/환불 항목 확인
   → 최종 승인

   ↓
   Step 4: 자동 지급 (상태: SETTLED)
   → 은행 송금 / GCash 송금
   → payment_date 기록

   ↓
[월말]
   Step 5: 확인 (상태: CONFIRMED)
   → 은행 거래내역 대조
   → settlement_date 최종 기록

│

├─ rule_name
├─ customer_type & payment_method (조건)

└─ recovery_rate & platform_fee_rate (설정)

🔌 API 엔드포인트 (7가지)
================================================================================

1. POST /api/settlements/company/calculate
   → 월간 정산 자동 계산 및 생성
   입력: company_id, year, month
   출력: CompanySettlement (status: draft)

2. GET /api/settlements/company/{company_id}/{year}/{month}
   → 특정 월 정산 조회
   출력: CompanySettlement

3. GET /api/settlements/company/{company_id}
   → 업체의 모든 정산 목록
   필터: status, year
   출력: CompanySettlement[]

4. PATCH /api/settlements/company/{settlement_id}/approve
   → 정산 승인 (draft → approved)
   입력: approved_by, notes

5. PATCH /api/settlements/company/{settlement_id}/settle
   → 정산 지급 (approved → settled)
   입력: payment_method, payment_date, paid_by

6. PATCH /api/settlements/company/{settlement_id}/recovery-rate
   → 외상 회수율 수기 갱신
   입력: recovery_rate (0~100)
   부작용: recovered_amount, net_settlement 자동 재계산

7. GET /api/settlements/company/{settlement_id}/transactions
   → 정산의 구성 거래 조회
   출력: SettlementTransaction[]

├─ settle_payment() - 정산 지급

💾 데이터베이스 마이그레이션
================================================================================

필수 생성 테이블:
1. company_settlements (월간 정산)
   - 1 company × 12 months = 최대 12개/company/year
   - 인덱스: (company_id, year, month), status, payment_date

2. settlement_transactions (거래 추적)
   - 1 settlement × N bookings
   - 인덱스: company_settlement_id, booking_id, transaction_type

3. settlement_rules (정산 규칙)
   - 규칙 추가/수정으로 유동적 처리
   - 예: 새로운 결제 수단 추가 시 rule 추가

선택 마이그레이션 (bookings):
   - settlement_type VARCHAR(50) - 정산 유형
   - settlement_id INTEGER - 해당 정산 기록 FK
   - recovery_rate DECIMAL(5,2) - 회수율

================================================================================
📋 정산 시나리오 (5가지)
================================================================================

Scenario 1: 비회원 고객 (Guest)
   입력: 드롭인 고객, 현장 현금 결제 2,000 PHP
   → settlement_type = 'settled'
   → recovered_amount = 2,000 (100%)
   결과: 즉시 정산액에 반영

Scenario 2: 업체 크레딧 (Company Credit)
   입력: ABC Corp 직원 이용권 5건 × 2,000 = 10,000 PHP
   → settlement_type = 'pending'
   → recovery_rate = 80% (수기 입력)
   → recovered_amount = 8,000
   결과: 외상액 10,000 중 8,000만 정산액에 반영

Scenario 3: 제외 정산 (Waived)
   입력: 신규 고객 프로모션 1,500 PHP
   → settlement_type = 'waived'
   → recovery_rate = 0%
   → platform_fee도 부과하지 않음
   결과: 정산액에 제외, 내부 회계에만 기록

Scenario 4: 분쟁 및 환불
   입력: 고객 불만 환불 500 + 서비스 분쟁 200
   → total_deductions = 700
   결과: net_settlement에서 700 차감

Scenario 5: 월간 종합 정산
   입력: Makati Spa Center, 5월
   - 비회원 150,000 (회수 100%)
   - 외상 100,000 (회수 80%)
   - 제외 50,000 (회수 0%)
   계산:
   - guest_revenue = 150,000
   - recovered = 80,000
   - platform_fee = (300,000 - 50,000) × 25% = 62,500
   - deductions = 8,000
   결과:
   - net_settlement = (150,000 + 80,000) - 62,500 - 8,000 = 149,500 PHP
